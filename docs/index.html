Especificación

Dominio y requerimientos

Primero el dominio (etapa 1). Después los requerimientos, con el formato de la práctica: RF / RFN, necesidades, deseos, expectativas, usuario o sistema.

Requerimientos

Escríbanlos a partir del debate. Uno por enunciado, atómico.
RF / necesidad / deseo / sistema: El sistema debe + verbo + objeto + condición observable.
RFN / expectativa: una cualidad medible (tiempo, disponibilidad, usabilidad).
Usuario: El usuario quiere… en lenguaje de negocio, sin detalle técnico.
La IA compara lo debatido con lo escrito, corrige la forma y deja todo en el historial.

Conexión del laboratorio

La URL y las claves de Supabase no se muestran ni se guardan en el repositorio. El docente las carga como secretos de GitHub; al publicar, el sitio las usa sin exponerlas en el código.

En el repositorio: Settings → Secrets and variables → Actions. Secretos: SUPABASE_URL, SUPABASE_ANON_KEY, AI_KEY_GROQ, AI_KEY_GEMINI. Variable opcional: AI_PROVIDER (groq o gemini).

Después: Settings → Pages → Source → GitHub Actions. Cada push vuelve a publicar el laboratorio.

Todavía no hay aula remota. El trabajo queda en este navegador.
